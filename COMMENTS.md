# Quill design notes

Go code in this repo carries no comments; notes live here.

## Build and test

- `export PATH=$HOME/.local/go/bin:$HOME/go/bin:$PATH`
- GUI build on this machine: `go build -tags wayland ./cmd/quill` (no X11 dev headers installed). Without the tag, anything that compiles `cmd/quill` (vet, test) fails on missing X11 headers, so use the tag there too.
- Full check: `go vet ./internal/... && go vet -tags wayland ./cmd/... && go test -race -tags wayland ./...`
- Real transcript probe: `QUILL_PROBE_TRANSCRIPT=<jsonl> QUILL_PROBE_OUT=<dir> go test -tags wayland -run TestRealTranscriptProbe ./cmd/quill/` renders a real session off-screen (bottom and scrolled up) and logs the render time.
- Screenshots: `DESK_SHOTS=1 go test -tags wayland -run Screenshots ./cmd/quill/` writes `.shots/{history,permission,centered,terminal,new-session}.png` (git-ignored). They are rendered off-screen by Fyne's test driver with fixture transcripts and the fake claude.

## Layout

- `internal/protocol`: stream-json line parsing (`Event`), control request/response builders (initialize, interrupt, set_permission_mode, set_model, remote_control, can_use_tool answers).
- `internal/chat`: conversation model shared by live streams and saved transcripts (`Conversation.Apply(event)` returns the items that changed). Item kinds: user, assistant (streams via text deltas), tool (one-liner with summary, input, result, diff for Edit/Write/MultiEdit), permission, notice, error, thinking.
- `internal/transcript`: scans `~/.claude/projects/*/*.jsonl` (read-only, cached by mtime+size) and loads one transcript into a `chat.Conversation`.
- `internal/session`: one headless `claude` process per app session.
- `internal/live`: finds sessions open in a terminal and releases them for takeover.
- `internal/account`: auth status / login / logout through the CLI.
- `internal/fakeclaude`: a scripted stand-in for the CLI. Test binaries re-exec themselves with `CLAUDE_DESK_FAKE=1` to become it. Prompts: `write` (Write + permission prompt), `demo` (thinking, text, Bash with result, Edit + permission prompt), `slow` (streams until interrupted), anything else echoes. `FAKE_ARGS_OUT` records argv, `FAKE_IGNORE_EOF` simulates a hung process.
- `cmd/quill`: Fyne UI (`desk.go` sidebar, header, bottom bar, process wiring; `chatview.go` conversation rendering; `widgets.go` max-width layout, Enter/Shift+Enter entry; `theme.go` dark theme).

## How a session is driven (verified with two tiny real haiku runs, fixtures in internal/protocol/testdata)

`claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --permission-prompt-tool stdio [--resume <id> | --session-id <uuid>] [--model M] [--permission-mode M]`

- cwd = project folder, own process group, the user's normal login (no API key, no env changes). An `initialize` control_request is sent right after start.
- New sessions get a fresh UUID via `--session-id`, so the sidebar row, the transcript file and the process agree from the first message. Past sessions are resumed with `--resume <id>` on the first send; the process then stays up between turns.
- CLI permission modes: acceptEdits, auto, bypassPermissions, manual, dontAsk, plan. The app offers default (flag omitted), acceptEdits, plan, auto. Model picker: default (flag omitted), fable, opus, sonnet, haiku. Changing either on a running session sends set_model / set_permission_mode.
- Messages are user lines `{"type":"user","message":{"role":"user","content":text}}`.

## Permission prompts

Plan-first approval (default on, sidebar "Plan first, then approve all", preference `planFirst`; `planGate`): the first `can_use_tool` of a request is denied with `planAskMessage` (nothing runs; Claude is asked to list every command/change and stop), shown as a small "held" line. When that turn ends, a Plan card appears ("Approve plan & run all" / "Don't run"). Approving sends `planGoMessage` and sets `runAll`, so every `can_use_tool` is allowed automatically (`PermAutoAllowed`; not shown in the chat since 2026-11-20, user: "don't show bash : approved with the plan"). With the option off, prompts work one by one as below.

Plan-first fixes (2026-11-19, user hit all three): (1) Approvals typed on another device (Remote Control) never reached `sendTo`; `planGate` now also reads `user` events (text items after `CleanUserText`): an `isApproval` text or `planGoMessage` calls `approveNow` (approves pending Plan cards, `runAll` for the current turn), any other user text ends the approval. (2) `runAll` used to reset at every `result`, so a background task notification that resumed the turn mid-plan was blocked again; now the approval lasts until the next real request (non-approval text via `sendTo` or a `user` event; `planGoMessage` itself does not end it); `runAllNext` still moves into `runAll` at `result`. (3) Read-only requests pass without a plan (readonly.go): `readOnlyRequest` allows Read/Grep/Glob/LS/ToolSearch/ListAgents/NotebookRead and Bash commands whose every part is read-only. `shSegments` is a small quote-aware shell lexer: it splits on unquoted `;` `&&` `||` `|` `&` and newlines (so `grep -E "a|b"` is one command), strips quotes, drops `#` comments, and rejects `$(`/backticks outside single quotes, unquoted `(`/`)`, heredocs, `<(`/`>(` and any output redirect except to `/dev/null` or `>&1`/`>&2` (`< file` input is fine). Variables assigned earlier in the same command (`Q=/repo; git -C $Q log`) are expanded; unknown variables mark the word unknown, and the commands with argument checks (`argChecked`: sed, find, git, sort, tree, rg, file, uniq, awk, journalctl, date) reject unknown words so `X=-i; sed $X` can't slip through. Assignments to PATH, IFS, LD_*, GIT_*, *PAGER and similar are refused. Program names with a path count only from /usr/bin, /bin, /usr/local/bin, /usr/sbin and ~/.local/bin. Per program: `readOnlyCommands` list (incl. cd, test, [), `git` with optional `-C dir`/`--no-pager` and a subcommand in `readOnlyGit`, `sed -n` print ranges only, `find` without -delete/-exec/-ok/-fprint/-fls, `awk` without -f/system()/pipes/print >, `journalctl` without vacuum/rotate/flush and friends, `date` without -s. User extras (sidebar "Read-only commands...", preference `extraReadOnly`, one per line) match by word prefix after the same lexing, so `pzlock status` also covers `~/.local/bin/pzlock status 2>&1 | head` (user request 2026-11-20: 'status' cost 3 turns). Replaying the 66 commands plan-first had held in real transcripts: 28 now pass, the rest are real writes, heredocs, loops or `$(...)`. (5) A reply that is only a list of step numbers ("1-4", "1,3", "steps 1 to 3", "1 2 4"; `isStepList`, at least two numbers) approves the plan only when it names EVERY step of the pending plan (`approvesPlan` -> `coversPlan`, used by `sendTo`, `user` events and `approvedInTranscript`). "1-4" means 1 through 4 (`stepNumbers` expands ranges; backwards ranges fail). The step count is the highest number starting an unindented line of the plan text (`planSteps`: "1.", "1)", "(1)", "**1.**"); a plan with no numbered lines needs a real yes. 1-4 on a 6-step plan is an ordinary reply (cancels the card as any new request does). Without a plan card it is an ordinary answer (user decisions 2026-11-20: option b, then "only when it covers every step"). (4) The Plan card also appears without a blocked request when the turn's last assistant text ends with a question containing "approve" on its last line (`Conversation.AsksApproval`).

- `--permission-prompts host` alone does not route anything to the app (the real Write was denied). With `--permission-prompt-tool stdio` the CLI emits `control_request` subtype `can_use_tool` (tool_name, input, tool_use_id, permission_suggestions).
- Answer: `control_response` success with `{behavior:"allow", updatedInput}` or `{behavior:"deny", message}`. "Allow always (this session)" also sends `updatedPermissions`: the CLI's own suggestions re-targeted to destination `session`, or an `addRules` rule for the tool name. Verified for real.
- Auto-mode blocks (blocked.go): a Bash/tool result containing "auto mode classifier" shows a card (reason, command). Approving in chat can't lift the classifier. "Approve and retry" switches an auto session to default for that reply (`restoreMode` brings auto back at `result`), sends `retryPrefix` + the command, and when the retried `can_use_tool` has exactly the blocked command (`retryCmd`), `planGate` allows it at once (`PermRetryAllowed`): the click on the card is the approval, so no second Allow (later list 1c, user 2026-11-20: a trash cleanup took three approvals). A different command still gets the normal prompt. "Always allow..." opens a dialog with editable rules, one per line, suggested per non-read-only segment by `suggestedRules` (program plus a plain subcommand word, `Bash(gio trash *)`; shell keywords like for/do/done skipped; other tools suggest the tool name), and a scope: this session (`destination:"session"`) or all sessions (`"userSettings"`, the CLI writes ~/.claude/settings.json itself). The rules go out with the retry's allow as `updatedPermissions` addRules `{toolName, ruleContent}` (`protocol.AllowWithRules`, `PermRuleAllowed`). Allow rules let Bash skip the auto-mode classifier unless the CLI setting classifyAllShell is on (seen in CLI 2.1.311 strings). Verified for real 2026-11-20 with a haiku probe: destination localSettings wrote `Bash(touch *)` to .claude/settings.local.json and the command ran.
- `control_cancel_request` and the end of a turn mark open prompts "No longer needed". Other incoming control requests get an error reply so the CLI never waits.

## Stop, close, lifecycle

- Stop button: control_request `interrupt` (real run ended with terminal_reason `aborted_streaming`); SIGINT only if the request fails. An interrupted turn shows an "Interrupted" notice, not an error, and "No response requested." filler is hidden.
- Shutdown (`Process.Stop`): interrupt if busy, close stdin, wait, SIGTERM to the group, SIGKILL. Closing the window with running sessions asks first, then stops them all in parallel.
- Switching sessions only switches the view; processes keep running and their events keep updating their own conversation.
- Status dots: running (turn in progress), waiting for you (pending permission), idle (process up, no turn), error (process exited with an error), open in a terminal.

## Remote Control

The header shows status only ("● Remote Control on" / "Remote Control off" / "Remote Control..." while connecting; no link, user 2026-11-19); there is no per-session checkbox any more (user 2026-11-19). `setRemoteControl` stays for tests and future use.

`--remote-control` is for interactive sessions only, but a headless session accepts control_request `{subtype:"remote_control", enabled:true|false}`; enabling returns `session_url` and `connect_url` (verified for real). The header has a per-session "Remote Control" checkbox, off by default; turning it on starts the process if needed and shows an "Open remotely" link. It resets to off whenever the process restarts. "Remote Control for every session" (sidebar, preference `autoRemoteControl`, default ON, user 2026-11-19) turns it on quietly (no chat notice) every time Quill starts a Claude process (`autoRemote` from `ensureProcess`), so it survives restarts and live updates.

Remote Control names carry Quill's folder (rcnames.go, user 2026-11-19, for the Android app in Projects/quill-android). For every running session with Remote Control on, Quill sends control_request `{subtype:"rename_session", title:"<Folder> · <Title>", source:"host"}`. It does this after RC turns on and on every `rebuildRows` when the name changed (move, rename, automatic demotion, folder rename). `rowPlace` records which top folder each session landed in. The CLI relays the title to claude.ai (verified for real: both names showed) and also appends a `custom-title` record to the transcript, which the user accepted. It counts as a user rename, so the CLI stops auto-titling that session, and `claude --resume` in a terminal shows the prefixed title. That is why sessions are only renamed once they have a real title (`transcript.Info.Named`: custom/ai/summary title, or a Quill rename); prompt-only sessions wait for their ai-title. `sideOrg.RC[id] = {sent, base}` is saved before sending, and when a transcript title equals `sent`, Quill shows `base` instead (`unRCTitle` in `refresh`), so its sidebar never shows the prefix and prefixes never stack. A different title (renamed on claude.ai) is taken as the new base. Failed renames are not retried until the name changes.

## Phone folder sync (phonesync.go, internal/folders; user 2026-11-19)

Quill for Android (Projects/quill-android) groups sessions by Quill's folders. Since e0d62ee, Remote Control names are plain titles, so the folders travel in a separate file instead:
`{"version":1,"updatedMs","updated","host","order":[folder titles in d.groups order],"sessions":{"session_<claude.ai id>":"<folder title>"}}`.
- The claude.ai ids come from Remote Control responses (`session_url`): `rememberRC` in autoRemote/setRemoteControl stores rcID → Quill session id in pref `phoneRC` (cap 4000). Every rcID a session ever had keeps mapping to its current folder.
- `phoneChanged` (end of rebuildRows) republishes with a 1 s debounce, only when the content changed (`File.SameContent`), so updatedMs only moves forward on real changes.
- Three outputs, combined by the app (newest updatedMs wins, last copy cached):
  - Local network: Settings → Phone → "Pair phone..." starts `folders.Server`. It is HTTPS with a self-signed ECDSA cert in ~/.config/quill/phone (QUILL_PHONE_DIR), and the phone pins its SHA-256 fingerprint. Only `GET /folders.json` with header `X-Quill-Key` (32 random bytes, constant-time compare) is answered, other requests get 403/404. The random port 20000–60000 is saved in `phonePort` (Fedora's FedoraWorkstation zone allows 1025–65535). It is off until paired (`phoneServe`). The dialog shows a QR code (rsc.io/qr, BSD, packaged as LICENSE.qr) of `quillpair://pair?h=<LAN IPs>,<host>.local&p&k&fp&f&g&n`, with Copy pairing link, New key (unpairs) and Stop sharing.
  - Synced file: "Write folders file to..." writes quill-folders.json atomically (temp + rename) into a folder the user syncs (Syncthing, Nextcloud, Drive, ...). Pref `phoneDir`.
  - Secret gist: "Publish to a secret gist" (only shown when `gh` is on PATH; QUILL_GH overrides) runs `gh gist create`, then `gh gist edit <id> --filename quill-folders.json <file>` at most once a minute. Pref `phoneGist` = owner/id, included in the pairing link.
- Test: TestPhoneSyncFileServerAndGist (fake gh script, real TLS server, pinned fingerprint, moves update the file).



`~/.claude/sessions/<pid>.json` (pid, sessionId, cwd, procStart, kind, status). A session counts as open elsewhere when that pid is alive, not a zombie, and its `/proc/<pid>/stat` start time equals procStart; the app's own children are excluded. Exiting an interactive CLI session can leave it held by a background process (`kind:"bg"`, `claude bg-spare`), which is why "exited in Konsole, still blocked in Quill" happened.

Input stays enabled with a note. Sending takes over (`desk.takeOver`): `live.Finder.Release` runs `claude stop <sessionId>` for bg sessions, otherwise SIGTERM, waits up to 5 s, then SIGKILL; then the transcript is reloaded and the session is resumed with the message. If the file says `status:"busy"` a confirm dialog comes first. The Remote Control checkbox stays hidden until the takeover. Transcripts of held sessions reload when the file changes (5 s poll).

## Live update (reload.go)

Go can't hot-swap code, so a new build takes over in place. `watchBinary` polls the running executable (symlinks resolved) every second; once it changed, is at least 1 s old, executable and starts with ELF magic, `trySwap` runs when nobody typed for 15 s (or right away after `quill --reload`), no permission prompt is open and no takeover is in progress. Claude sessions are NOT stopped: `session.Process.Handoff` stops the reader cleanly (read deadline, keeps a partial line), clears CLOEXEC on the child's stdin/stdout pipe ends (via SyscallConn, never `File.Fd()`, which would switch the pipe to blocking mode and break read deadlines; `Attach` sets the fds non-blocking (and close-on-exec) again before `os.NewFile` so they stay pollable; after an exec (`Handoff.FromExec`) it reuses the inherited fd, inside the same process (failed exec, tests) it dups it so two os.Files never share one fd, otherwise the SECOND handoff hung forever: bug seen 2026-11-19; Handoff also gives up waiting for the reader after 3 s) and returns the pid + fd numbers; they go into $TMPDIR/quill-restore-<pid>.json together with the session, draft, window size, scroll and Remote Control state, then `syscall.Exec`s the new binary. The new process (`applyRestore`) reloads each handed session's transcript, then `session.Attach`es to the same child (same pid, still our child, so wait4 works) and keeps streaming, even mid-turn; Remote Control stays on because the CLI process never restarted. Child stderr goes to a temp log file (not a pipe), so nothing can block while Quill restarts. If exec fails, the sessions are re-attached in the same process. Sessions that could not be handed off are resumed with --resume (`restoreState.Running`). Build with `go build -o dist/quill.tmp ... && mv dist/quill.tmp dist/quill`, then `dist/quill --reload`.


What a live update keeps (user 2026-11-20 audit: "quill keeps dropping things that aren't saved"): queued messages of every session (`restoreState.Queues`, `saveQueues`/`restoreQueues`; restored in order in front of anything queued since, sent at once if the session is already idle); drafts of every tab, not only the visible box and split panes (`restoreState.Drafts` from `strip.drafts`); per-session state in `restoreState.Meta` (restore.go `sessMeta`): model and mode of every open session, including stopped ones (`d.session` would otherwise rebuild them as default/default, so a Local session resumed on Claude), new tabs with nothing sent yet (recreated from cwd), Approve-and-retry in progress (`restoreMode`, `retryCmd/Rules/Dest`), kmem intro pending (`kmemNew`), rotate card state, `lastClaude`, a kmem restart waiting for its handoff save (`kmemSave`, checked again at once if the session is already idle) and a summary restart still compacting (`compactFrom`; `resumeInterrupted` re-runs `compactInto`). Not kept (cosmetic): Quill's own notices/errors in the chat, dismissed blocked cards, unsent picks on an open question card. The prompt suggestion (greyed next prompt) of each handed session is saved too (`handedSession.Sugg`) and restored unless a newer one arrived or the session is busy again (user 2026-11-20: the message box lost the suggestion on every update).

## Background mode (background.go)

`quill --reload` sends "reload" over the instance socket: the running Quill swaps to the new build as soon as no turn is running, skipping the 15 s typing wait (`forceSwap`). Use it after every build.

Closing the window hides it (`confirmClose` -> `hideWindow`) when a system tray is available (`desktop.App`); sessions keep running. Tray menu: Show Quill, Quit (Quit shows the window and goes through `confirmQuit`, which asks before stopping running sessions, then `app.Quit`). Single instance: $XDG_RUNTIME_DIR/quill.sock; a second launch sends "show" and exits, the running one shows its window and answers "ok". After a live update (exec) the new process skips the check (QUILL_RESTORE set), re-creates the socket, and stays hidden if it was hidden (`restoreState.Hidden`, started with `app.Run()`).

## UI notes

- Chat text selection (textselect.go; user 2026-11-20 asked for "option 3 without the risk"): a `selLayer` widget sits on top of each chat view's box (last object of `v.inner`, kept last by `setBox`). It implements ONLY `fyne.Draggable`: the glfw driver picks one click target for Tappable/SecondaryTappable/DoubleTappable/Focusable/Mouseable together (window.go mouseClicked), so any of those on the layer would steal clicks from buttons and cards; Draggable is matched only once a drag starts. A drag highlights over the text as Fyne already drew it: `collectRuns` walks the box (`driver.WalkVisibleObjectTree`, positions minus the box's own position, otherwise the padding counts twice) for every `*canvas.Text`, skipping buttons, entries, selects, checks and radios, and notes the owning `*widget.RichText`; hit-testing measures each run with its own size/style/alignment, so headings, bold, inline code, code blocks, centered and wrapped lines line up (checked on a rendered screenshot). Copy maps the runs back to the owner's source (`Textual()` of each segment, newline after non-inline ones), so wrapped lines keep their original spacing; runs that can't be mapped fall back to the drawn text. Selection can span messages (owners joined by a newline). Copy: Ctrl+C (canvas shortcut; pressing in the chat unfocuses the message box) or the Copy button shown at the end of a selection; Escape (canvas OnTypedKey base handler) or a new drag clears it; switching sessions clears it. No double-click word select (would need DoubleTappable). glfw DragEvent: Position = current pointer, Dragged = movement since the last event, so the start is Position-Dragged on the first event (fyne/test.Drag sends the start point instead; tests call Dragged directly). Test: TestChatTextSelection.

- Background work counts as running (user 2026-11-20: "when sessions are testing, change status to run, don't show as idle"): `Conversation` tracks background task ids (`trackTask` on tool results: Bash "Command running in background with ID: X" or "moved to the background (ID: X)", Monitor results, Agent/Task results only when started in the background, so a finished foreground agent's agentId doesn't count; failed calls never count; TaskStop/KillShell end a task) and `taskNotification` ends one when a `<task-notification>` with that `<task-id>` has a final `<status>` (completed/failed/killed/stopped/...; progress notifications don't), read before the meta/hidden filter so notifications stay out of the chat. `deskSession.status` returns running while `conv.Background() > 0`, so sidebar, tabs and header show blue with no idle glow. `ensureProcess` clears the list for a new process (tasks die with it); a reattach after a live update keeps it (the transcript reload rebuilds it). Monitor/background-agent result wording was not sampled from real transcripts; the generic `ID:` match is an assumption.

- Tab chips glow by the same rules as sidebar rows (user 2026-11-20: "tabs are not following glowing rules"): each chip keeps one glow rectangle (`tabChip.glow`, between the card and the content) driven by `setGlow(status.color(), glowStrength)`: waiting/error pulse at full strength, idle a soft 0.3 glow, running and the active tab none. Closing a tab removes its glow from `glowBoxes`. Test: TestTabsGlowLikeSidebar.

- Approval cards follow "center messages" (user 2026-11-20): plan, permission, question, blocked and rotate cards align every label and status line with `v.align()`; status lines use `v.muted` (aligned canvas.Text) and the question card's radio/check groups are wrapped by `v.centered`. `setCenter` also drops `qcards` (cached open question cards), otherwise an open question kept its old alignment (an unsent pick on it resets). Test: TestApprovalCardsFollowCentering.

- Local slash commands (localcmds.go): the headless CLI rejects interactive-only commands ("/upgrade isn't available in this environment"), so Quill handles /upgrade (opens claude.ai/upgrade), /login, /logout, /clear (new session in the same folder), /model <name>, /exit|/quit itself before anything is sent; they are listed first in the / suggestions and replace the CLI's entries of the same name.

- Auto-scroll: the chat follows new messages/thoughts/steps while the view is at the bottom (`follow`); scrolling up (OnScrolled, not caused by Quill itself) stops following, and a glowing "Latest" button (pulsing accent behind it) appears at the bottom of the chat; clicking it glides down to the newest content (320 ms ease, `glideBottom`) and resumes following.

- Speech to text (stt.go): mic button above Send. Fully local: `pw-record` (16 kHz mono) -> `ffmpeg` clean-up -> whisper.cpp `whisper-cli -nt -np` with `~/.local/share/quill/models/ggml-base.en.bin` (overrides: QUILL_WHISPER, QUILL_WHISPER_MODEL); the temp audio folder is deleted after transcription, the text is appended to the input (never sent automatically). First click shows a privacy notice (nothing collected or sent to Anthropic; preference `sttNoticeShown`). If the engine is missing, a dialog shows the one-time setup command (`sttSetupCommand`: clone whisper.cpp v1.7.6, CPU build, download the model). Status shows on the live line ("● Listening...", "Turning speech into text...").

- Flicker: never refresh the whole main pane on chrome updates; `setLabel`/`setText` and the select/usage guards only touch widgets whose content changed (Fyne re-lays out containers when a WIDGET's min size changes, but not for canvas.Text, so the header is refreshed explicitly when its subtitle or Remote Control text changes).

- Centered Markdown lists: Fyne's list layout ignores alignment, so in Center mode lists become paragraphs prefixed with "• " / "1. " (`centerLists`, nested lists indented); Left mode keeps real lists.
- Message layout: message text alignment is switchable in the sidebar ("Text: Left / Center" radio next to the Remote Control option; preference `centerText`, default Center); user messages in a dark full-width bubble, Claude's replies plain (the left/right split was removed).

- Text sizes: general UI text is one size (13 px, caption = text); user and assistant messages use `msgTheme` (16 px) via a ThemeOverride (`msgText`). A live status line under the chat frame, bottom left, outside the scroll (`chatView.live`, `liveText`; fixed height so the chat never jumps) shows "✻ Thinking...", the running tool, or "✻ Working..." while a turn runs (hidden while reply text streams).

- Usage panel (usage.go) in the blank space right of the chat, vertically centered, 36 px from the chat column (shown when the margin is >= 230 px and the full panel fits in height, `usageLayout`): plan usage from the CLI's `rate_limit_event` (`rate_limit_info.unifiedWindows.five_hour / seven_day`: utilization, resetsAt; last value saved in preference `rateLimit` and shown "as of"), this session's TRUE total tokens (in + out + cache read + cache write, from its transcript: `transcript.Info.Usage`, assistant `message.usage` deduplicated per message id) plus context, and today's / last 7 days' true totals on one line (compact, user 2026-11-19) across all transcripts (`Info.Days`, keyed by local date).

- Key hints (Enter send, Ctrl+Enter stop & send, Shift+Enter new line, / commands) sit in small grey text, right-aligned on the stats line under the input (`fitRight`: hidden when there is no room, so small windows stay usable) (where the folder name used to be; the folder is already in the header). The empty input just says "Message Claude".

- The chat bounds show as a thin outline only (`chatView.frame`, transparent fill, white stroke ~11% alpha); the scroll container sits INSIDE the outline so messages never draw over or under it (the scrollbar is inside the frame). No shadows: `ColorNameShadow` is transparent in the theme, which removes the dark overlay Fyne's scroll container draws at the top edge when scrolled (popups lose their drop shadow too).

- Slash commands (commands.go): the list comes from the `initialize` control response (`commands`: name, description, argumentHint). `session.FetchCommands` gets it at startup from a throwaway process in $HOME (no prompt, so no transcript; it does fire SessionStart hooks); a running session's own list (`Process.Commands`, includes project skills) replaces it. Typing `/word` shows up to 8 matches (prefix first, then substring) inline above the input (NOT a Fyne PopUp: overlays take keyboard focus, so typing froze while the list was open); Up/Down, Tab completes, Enter completes or sends when the full command is already typed, Esc closes.
- Steps live in the chat: consecutive tool steps collapse into one wrapping row of chips (✓ green done, ✗ red failed, … running + tool name; `stepRun`/`flowLayout`); clicking a chip opens that step's input/output inline under the row in `smallTheme` (`toggleStep`, state per *chat.Item). The separate steps panel below the input was removed (user 2026-11-19).
- Performance: stream events update the Conversation immediately but the UI is redrawn at most every 50 ms (`queueUI`/`flushUI`, batched per session; results, permission prompts, init and suggestions flush at once). - transcript: synthetic and real transcripts, scanner grouping and cache.

## Gaps / v2 ideas

- No real end-to-end run through the GUI itself (process wiring is covered with the fake; the protocol with real fixtures).
- Thinking text, images, subagent (side-chain) activity and todo lists are not shown.
- No attachments, slash-command palette, session rename/delete, or per-tool "always" rules beyond what the CLI suggests.
- Transcript reloads are full reloads (fine for normal sizes; very large transcripts load in the background).
- Terminal detection relies on `~/.claude/sessions/*.json`; if the CLI changes that format the "open in a terminal" state disappears (sessions then look idle, and sending would start a second process on the same id).

## Bundled Fyne (third_party/fyne)

Quill builds against a patched copy of Fyne v2.8.2 in `third_party/fyne` (go.mod `replace`). Changes: `widget/entry.go` gets an `Alignment` field on `Entry` (applied to the text and placeholder segments; `CursorPosition` adds `rowAlignOffset` so the cursor lines up with centered text), and `internal/driver/glfw/window_desktop.go` gets `Maximized`, `Maximize` and `Position` on the window so Quill can reopen maximized (and at the same position on X11) after an update. `driver/walk.go` (new file, additive) exports `driver.WalkVisibleObjectTree`, a wrapper around the internal walker, for chat text selection. The diff is `third_party/fyne.patch`.

To upgrade Fyne: copy the new version from the module cache into `third_party/fyne` (without `_test.go`/`testdata`), re-apply the patch (`patch -p1 -d third_party/fyne < third_party/fyne.patch`), fix any rejected hunks by hand, run the tests (`TestCenteredTyping`).

## Built-in speech to text (internal/whisper)

whisper.cpp v1.7.6 is bundled in `third_party/whisper.cpp` (CPU backend only; the GPU backends, examples, tests and bindings were left out) and linked statically through cgo. Run `scripts/build-whisper.sh` once before `go build`/`go test`; it builds the static libraries into `third_party/whisper.cpp/build` (git-ignored) with AVX2/FMA/F16C so the binary runs on any x86-64 CPU from about 2013 on. `-f` forces a rebuild.

Microphone capture uses malgo (miniaudio), which loads PipeWire/PulseAudio/ALSA at runtime, so users need no extra packages. Models are downloaded inside Quill on first use into `~/.local/share/quill/models`: `ggml-base.en-q5_1.bin` for English, `ggml-base-q5_1.bin` for every other language (about 57 MB each).

Live transcription (`live.go`): audio stays in memory; every 400 ms the audio since the last pause is re-transcribed with `audio_ctx` shrunk to the clip length (the main speed-up), nothing runs during silence, and a phrase is committed after 0.7 s of quiet or 20 s of speech. The model is freed 5 minutes after the last use.

## Crash keeper (cmd/quill/keeper.go)

Starting `quill` runs a small keeper process that launches the window as a child (env `QUILL_KEEPER` = keeper socket). The window sends each Claude session's stdin/stdout pipes to the keeper over the socket (SCM_RIGHTS) when a session starts, when an approval request arrives or is answered, and drops them when the session ends; it also reports the open session. Because the keeper holds copies of the pipes, Claude never sees EOF when the window dies. If the window exits abnormally (signal other than TERM/INT/HUP, or a non-zero code) the keeper starts a new window with the pipes as extra files (fd 3, 4, ...) and a restore file, and the window re-attaches exactly like after a live update. Restarts back off from 0.5 s to 30 s but never stop, so sessions only end when Quill itself ends them. A normal quit (exit 0) closes the keeper's copies. A live update from a window started before the keeper existed execs into the keeper with the handed-off pipes (`keeper.adopt`), so protection starts without a restart; if the keeper cannot start, the update falls back to the plain window path. `QUILL_NO_KEEPER=1` disables it.

Sessions re-attached after a crash are no longer children of the window, so `session.Attach` falls back to polling the PID (`waitForeign`) when `Wait` returns ECHILD.

## Updater and release signing (internal/updater, cmd/quill/update.go, cmd/quill-sign)

Installed builds (RPM under /usr/libexec/quill, or an AppImage via $APPIMAGE) check https://api.github.com/repos/katachinosekai/quill/releases/latest after 15 s and every 6 h ("Check for updates" in Alignment settings). Dev builds (version "dev") never update. An update is only installed when:
1. the release has `SHA256SUMS` and `SHA256SUMS.sig`, and the signature verifies with the ed25519 public key built into `updater.PublicKey`;
2. the package name matches the release version exactly (`quill-X.Y.Z-N.fcNN.x86_64.rpm` / `Quill-X.Y.Z-x86_64.AppImage`), and the version is strictly newer;
3. GitHub's asset digest equals the signed checksum, and the downloaded bytes hash to it too;
4. every request is HTTPS to github.com / api.github.com / *.githubusercontent.com (redirects too), with size limits.
AppImage installs swap the file in place (keeping `.old`) and Quill execs into it with the usual session hand-off. RPM installs run `pkexec dnf install -y -- <file>` (no shell), and the binary watcher then live-updates.

The private signing key lives only at `~/.config/quill-release/release.key` (mode 600, never committed). `go run ./cmd/quill-sign -genkey` created it once. `scripts/build-packages.sh` copies this version's packages (plus the Android APK) into `dist/release-<version>/` and signs them. Upload `SHA256SUMS` and `SHA256SUMS.sig` with the release, or the updater refuses it. If the key is lost, ship a build with a new public key; older installs then can't auto-update to it.

## Restart as new session (relaunch.go)

The old conversation is compacted by a tool-less `claude -p --no-session-persistence` call (same model, run in the private runtime dir so it never shows up as a session). Its input is trimmed: user and Claude messages up to 4,000 characters each, tool calls as one-line summaries without output, 120,000 characters in all. The hand-off is the brief plus the last 6 messages trimmed to 800 characters each. If compacting fails or takes over 3 minutes, the old trimmed hand-off (last 40 messages) is sent instead. While compacting, the new session queues anything you send. The old transcript is never changed.

## kmem sessions (kmem.go; user 2026-11-20: "kmems are replacements for notes so kmems should follow their sessions")

Only when a `kmem` binary is on PATH (`kmemAvailable`; tests set `kmemOff`, or `kmemRun` to stub it). Each session can carry a kmem name (`sideOrg.Kmem`, session id -> name, shown as "kmem NAME" in the sidebar meta line, removed on delete, editable via the session menu "kmem name..."). The new-session naming dropdown has a Memory select: "New kmem" (default; name = slug of the title, `kmemSlug`, made unique against `kmem handoff list` and other sessions; the first message the user sends is prefixed with `kmemIntro` telling Claude its kmem name), "Resume NAME (saved ...)" for each handoff (sets the name, title defaults to it, sends `kmem-resume NAME --print` output, or a built-in prompt when that script doesn't know the name), or "No kmem".

Auto-link: the transcript scan reads a kmem name from the first prompt (`transcript.KmemName`: `kmem handoff get NAME` from a kmem-resume prompt, or a typed `kmem-resume-NAME`), and `linkKmem` sets it on sessions that have no entry yet and only if no other session uses that name. Clearing the name in "kmem name..." stores an empty entry, so it isn't linked again.

Restart as new session on a session with a kmem name: instead of compacting, Quill sends `kmemSaveMessage` asking the old session to run `kmem handoff save NAME` (kmem commands, plus read-only ones, are allowed without a plan round while `kmemSave` is set). After each of its turns (`kmemAfterTurn` on `result`) Quill checks `kmem handoff list` for NAME saved after the request (2 s slack, second precision). Saved: `replaceWith` starts the new session (same title, folder, model, mode, place, tab), moves the kmem name to it, sends the resume prompt, and `deleteSession` removes the old one (user decision: it's stored in kmem and won't be used). Not saved: if the turn ended with a plan card or an approval question (plan-first held the save), Quill keeps waiting and says so; otherwise the restart is cancelled with a notice and nothing is deleted (one extra turn is tolerated if the session was mid-turn when asked). Seen for real 2026-11-20 with PZ Launcher: plan-first held the first turn, the restart was cancelled, the save came a turn later; on the retry Claude did not re-save ("already saved a moment ago"), so the request now says to run it again, and a save by the same session (handoff record contains "session cs:<id>)") up to 10 min before the request also counts (`kmemRecentSave`). Sessions without a kmem name keep the compacting restart.

## Auto-handoff (autohandoff.go; kmem task tf37f4c, policy decision f74ad5e, user go 2026-11-20)

Only with kmem available. After every turn (`result`, after `kmemAfterTurn`) `checkAutoHandoff` compares the session's context (`conv.Stats.ContextUsed/ContextMax`, from the result's last iteration and modelUsage contextWindow) with the policy from `kmem handoff policy` (expected `soft=N hard=N mode=auto|ask|off`, refreshed every 10 min; anything else, including the command not existing yet, means the default 50/75/auto). It acts only at a safe point (`safePoint`: process running, turn over, nothing queued, no pending prompt/question/plan card, no approval question in the last reply, no kmem restart or compaction in progress). Soft: a Rotate card (`chat.Rotate`, "Rotate now" / "Not now", or "kmem name..." when the session has none), asked once per level (soft, then hard). Hard with mode auto and a kmem name: closes open Rotate cards, posts a notice and starts the kmem restart (`relaunchViaKmem`); the session's own `kmem handoff save` is the real safe-point check. A cancelled rotation is retried only after context grows 5 more points (`rotateTried`).

## Notifications (notify.go, internal/folders/events.go)

One event source feeds both outputs: attentionKind turns a chat event into approval, question, plan, finished or error. A process that exits unexpectedly also counts as error. Desktop notifications go over D-Bus with the desktop-entry hint, only for sessions you aren't looking at, and clicking one opens that session. Phone events go to the pairing server's GET /events (same key and pinned TLS) whether or not you're looking: a 200-event ring per boot, an inclusive `since` cursor, and `wait` long polls of up to 25 s, with the write deadline raised for that request only and at most 4 waiters. The events carry only ids, titles, folder names and the type, never message or tool content. The phone setting turns the endpoint off (404).
